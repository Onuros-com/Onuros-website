# Security policy

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability, exposed secret, or
privacy failure. Use GitHub's private security advisory flow when available, or
contact an organization owner privately.

Include the affected repository and revision, a minimal reproduction, impact,
and any suggested mitigation. Do not include private keys, seed phrases, real
user data, or credentials.

## Scope

Reports covering consensus, privacy, wallet recovery, mining, build, dependency,
or CI behavior are welcome. Pre-mainnet software is not approved for real funds.

## Disclosure

The maintainers will acknowledge a report, assess reproducibility and impact,
prepare a fix and regression test where appropriate, then coordinate disclosure.
